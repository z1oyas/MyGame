## Игровая концепция

2D top-down, лес → пекарня. Монстрик, влекомый запахом булочек, пробирается через лес к пекарне, уклоняясь от врагов.

**Враги:**
- Следящие вышки (`Tower`) — детектят игрока по зоне обзора/пересечению.
- Рабочие лесопилки — патрулируют/преследуют (пока не реализовано, код закомментирован).

**Предметы:**
- Ягоды — подбираются в инвентарь, при употреблении дают ~3 сек невидимости.
- Конфеты — выпадают из карманов рабочих, восполняют 1 жизнь (макс. 3).

**Поимка игрока:** при обнаружении — монстрика хватают и выбрасывают за пределы уровня, −1 жизнь из 3, уровень начинается заново. При 0 жизней — game over.

**Уровни:** пока один. Планируются головоломки — механика не определена.

## Текущее состояние кода (обновлено)

Основной цикл работает: карта рендерится, герой двигается, вышка детектит через overlap. **Игра запускается и работает стабильно** — баги B1, B2 (NPE при dispose) исправлены. Архитектурные проблемы (раздел ниже) пока не устранялись — актуальны, но не блокируют разработку новых фич.

### Известные баги

| # | Проблема | Критичность | Где |
|---|----------|-------------|-----|
| B1 | ~~`movingSheet` не инициализируется в конструкторах → `dispose()` кидает NPE~~ | ✅ Исправлено | `Hero.java:71`, `Tower.java:52` |
| B2 | ~~`movingSheet` в `Animated.makeAnimationPersona()` — локальная переменная затеняет поле интерфейса~~ | ✅ Исправлено | `Animated.java:15-16` |
| B3 | `KeyboardAdapter.getDirection()` возвращает мутабельный shared Vector2 — вызывающий код может испортить внутреннее состояние | Средне | `KeyboardAdapter.java:43` |
| B4 | `Tower.findHeroChecker(Vector2)` сравнивает float через `==` — почти никогда не сработает | Низко | `Tower.java:59` |
| B5 | ~~`Hero.render()` всегда берёт `walkAnimation.getKeyFrame(0)` в покое — `cheersAnimation` игнорируется~~ | ✅ Исправлено | `Hero.java:59` |
| B6 | `Tower.moveTo()` пустой — вышка не может двигаться (возможно, осознанно, но нарушает контракт интерфейса) | Низко | `Tower.java:46` |

### Архитектурные проблемы

| # | Проблема | Влияние |
|---|----------|---------|
| A1 | `Person` интерфейс слишком тонкий (только render+dispose) — логика коллизий вынесена в конкретные классы | Слабая связность |
| A2 | `Animated` смешивает фабричные методы (загрузка текстур) и рендер — нарушение SRP | Поддерживаемость |
| A3 | Нет управления состоянием игры — `Main` напрямую держит все объекты, нет абстракции экранов/систем | Масштабируемость |
| A4 | Магические числа везде (size=64, size=256, speed=10, камера 50×30) — нет констант/конфига | Поддерживаемость |
| A5 | `form` Rectangle в Hero/Tower — захардкоженные размеры, не совпадают с визуальными пропорциями спрайта | Точность коллизий |
| A6 | Закомментированный код врагов — заброшенная фича, засоряет кодовую базу | Гигиена кода |

### Платформенные ограничения

| # | Проблема | Влияние |
|---|----------|---------|
| P1 | Только `core` и `html` — нет desktop (LWJGL3) лаунчера | Нельзя тестировать локально без html:superDev |
| P2 | GWT backend ограничивает возможности libGDX (нет полного Box2D, ограничения рефлексии) | Ограничения фич |
